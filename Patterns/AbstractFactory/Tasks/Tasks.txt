================================Задача 1================================
Вы разрабатываете фреймворк для создания десктопных приложений,
который должен поддерживать три операционные системы: Windows, macOS, Linux.
Для каждой ОС нужно создавать нативные компоненты интерфейса: окна, кнопки, чекбоксы, текстовые поля, списки.
Компоненты для разных ОС несовместимы между собой — приложение должно использовать компоненты только одной платформы в рамках сессии.

Условия:
	1.При запуске приложение определяет текущую ОС и автоматически выбирает нужную стилистику
	2.Все компоненты (окна, кнопки, чекбоксы) должны быть стилистически единообразны под выбранную платформу
	3.Фреймворк должен позволять добавлять поддержку новой платформы (например, iOS, Android для десктопных приложений) без изменения существующего кода приложений
	4.Каждый компонент имеет свои специфические методы (например, для окна — минимизировать/развернуть, для кнопки — установить иконку)
========================================================================

================================Задача 2================================
Разрабатывается приложение для управления файлами в разных облачных сервисах:
Google Drive, Dropbox, OneDrive, Яндекс.Диск.
Каждый сервис имеет свой API, свою систему аутентификации (OAuth, токены, пароли),
свои форматы метаданных, свои лимиты на операции.
Приложение должно работать с одним выбранным сервисом в рамках сессии пользователя, но пользователь может переключаться между сервисами.

Условия:
	1.Каждый облачный сервис требует свой набор классов: аутентификатор, загрузчик файлов, скачиватель, удалятор, поисковик
	2.Клиентский код (модуль управления файлами) не должен знать, с каким именно сервисом работает
	3.Переключение между сервисами должно быть простым
	4.Каждый сервис имеет свои особенности: Google Drive — поддержка коллабораций, Dropbox — история версий, OneDrive — интеграция с Office
========================================================================

================================Задача 3================================
Вы создаете RPG-игру, в которой есть разные типы локаций: лес, пустыня, подземелье, горы.
Каждая локация требует создания набора связанных объектов: враги (гоблины/скелеты/драконы),
ресурсы (дерево/руда/кристаллы), ландшафт (деревья/кактусы/сталагмиты),
климатические эффекты (дождь/песчаная буря/туман).
Все объекты внутри локации должны быть стилистически согласованы (в лесу не могут встречаться пустынные враги).

Условия:
	1.Генератор мира должен создавать целостные локации, где все элементы соответствуют выбранному типу
	2.Нужна возможность легко добавлять новые типы локаций (например, болото, вулкан, арктика) без изменения существующего кода генерации
	3.Каждая локация может иметь свои уникальные механики (в пустыне — потребность в воде, в горах — повышенный расход выносливости)
	4.Игрок может перемещаться между локациями, и при переходе генератор должен создавать новый набор объектов для новой локации
========================================================================

================================Задача 4================================
Крупная компания выпускает финансовые отчеты в разных форматах и для разных регуляторов:
МСФО (международные стандарты), РСБУ (российские стандарты), GAAP (американские стандарты).
Каждый стандарт требует свой набор документов: баланс, отчет о прибылях и убытках,
отчет о движении денежных средств, пояснительная записка.
Формулы расчета, структура документов и требования к оформлению различаются в зависимости от стандарта.

Условия:
	1.Система должна уметь генерировать полный пакет документов для выбранного стандарта
	2.Все документы в пакете должны соответствовать одному стандарту (нельзя смешивать МСФО-баланс с РСБУ-отчетом)
	3.Добавление нового стандарта (например, японский J-GAAP) не должно затрагивать существующий код
	4.Каждый тип документа имеет свою логику валидации, свои правила округления и свои форматы чисел
========================================================================

================================Задача 5================================
Интернет-магазин продает аксессуары для автомобилей разных марок: Toyota, BMW, Tesla, Mercedes.
Для каждой марки автомобиля нужно подбирать совместимые аксессуары: коврики (форма под пол конкретной модели),
чехлы для сидений (с учетом анатомии кресел), органайзеры в багажник (с учетом геометрии багажного отделения),
накладки на пороги (с логотипом марки). Аксессуары для разных марок невзаимозаменяемы.

Условия:
	1.При выборе марки автомобиля система должна предлагать только совместимые аксессуары
	2.Каждый аксессуар имеет свои специфические характеристики (коврики — материал и глубина поддона, чехлы — тип ткани и способ крепления)
	3.Нужна возможность добавлять новые марки автомобилей без изменения основного кода магазина
	4.Аксессуары могут иметь перекрестную совместимость (например, коврики от Toyota Camry подходят на Lexus ES), и эта логика должна быть инкапсулирована внутри фабрик
========================================================================
