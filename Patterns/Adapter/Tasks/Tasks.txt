================================Задача 1================================
Ваше приложение для планирования путешествий долгое время использовало внутренний сервис погоды с интерфейсом IWeatherService,
который возвращает данные в формате WeatherData (температура, влажность, скорость ветра).
Вы решили перейти на более точный внешний API (например, OpenWeatherMap или AccuWeather),
но этот API имеет совершенно другой интерфейс: возвращает JSON, использует другие названия полей,
требует API-ключ и работает асинхронно.
Существующий клиентский код (модуль отображения погоды) уже написан и работает с IWeatherService.

Условия:
	1.Клиентский код нельзя менять — он ожидает синхронный метод GetWeather(string city)
	2.Внешний API возвращает данные в формате JSON с полями temp, hum, wind_speed, city_name
	3.Внешний API требует асинхронного вызова (async/await)
	4.Нужно добавить кэширование результатов на 10 минут, чтобы не делать лишних запросов
	5.Внешний API может возвращать ошибки (город не найден, превышен лимит запросов), которые нужно преобразовывать в исключения, понятные клиентскому коду

================================Задача 2================================
Вы разрабатываете приложение для обработки изображений,
которое долгое время работало только с форматом PNG через интерфейс IImageProcessor.
Недавно приложение решило добавить поддержку форматов JPEG, BMP, GIF и WebP.
Каждый формат требует своей библиотеки и имеет свой API:

JPEG использует JpegLib с методами DecodeJpeg(byte[] data) и EncodeJpeg(Image img, int quality)

BMP использует BmpLib с методами ReadBmp(string path) и WriteBmp(Bitmap bmp, string path)

GIF использует GifLib с методами LoadGif(Stream stream) и SaveGif(GifFrame[] frames)

Условия:
	1.Клиентский код работает только с интерфейсом IImageProcessor (методы Load(string path), Save(string path), Resize(int width, int height),
	ApplyFilter(string filterType))
	2.Нужно создать адаптации для каждого формата, чтобы клиентский код мог работать с любым форматом единообразно
	3.Нужно скрывать особенности каждого формата (например, GIF может содержать несколько кадров, JPEG имеет параметр качества)
	4.При добавлении нового формата не должны меняться существующие адаптеры и клиентский коd

================================Задача 3================================
В вашей компании разные команды используют разные библиотеки для логирования:

Команда А использует NLog с интерфейсом ILogger (методы Info(), Error(), Debug())

Команда Б использует Serilog с интерфейсом ILogger (методы Log.Information(), Log.Error())

Команда В использует LogNet с методами log.Info(), log.Error(), log.DebugFormat()

Вы создаете централизованную систему мониторинга,
которая должна работать с единым интерфейсом IMonitoringLogger (методы Log(LogLevel level, string message),
LogException(Exception ex), BeginScope(string scopeName)).
Переписывать существующий код логирования в каждой команде нельзя.

Условия:
	1.Нужно создать адаптации для каждой библиотеки логирования
	2.Нужно преобразовывать вызовы из формата IMonitoringLogger в специфичные для каждой библиотеки
	3.Некоторые библиотеки поддерживают структурное логирование (свойства), другие — только строки
	4.Некоторые библиотеки требуют инициализации (настройка файлов, уровней логирования)
	5.Должна быть возможность динамически подключать нужный адаптер через конфигурацию

================================Задача 4================================
Сеть магазинов использует разные модели платежных терминалов:

TerminalA (старый) имеет интерфейс с методами PrintCheck(string text), OpenCashDrawer(), ProcessCard(string cardData, decimal amount)

TerminalB (новый) имеет интерфейс с методами SendCommand(CommandType cmd, Dictionary<string, object> params), где CommandType — enum

TerminalC (внешний) работает через HTTP API с методами POST /api/payment, POST /api/receipt, GET /api/status

Ваша кассовая система ожидает, что терминал реализует интерфейс IPOSDevice с методами:

bool ProcessPayment(PaymentInfo payment)

void PrintReceipt(ReceiptData receipt)

void OpenDrawer()

string GetStatus()

Условия:
	1.Нужно создать адаптации для каждого типа терминала
	2.Нужно обрабатывать специфические ошибки каждого терминала и преобразовывать их в единые исключения
	3.TerminalA требует синхронных вызовов, TerminalB и TerminalC — асинхронные
	4.Некоторые терминалы требуют дополнительных шагов (например, TerminalC нужно сначала авторизоваться по токену)
	5.Кассовая система должна работать с любым терминалом без изменения кода

================================Задача 5================================
Старое приложение работало с базой данных через прямой SQL-доступ и использовало интерфейс ILegacyDataAccess с методами:

DataTable ExecuteQuery(string sql)

int ExecuteNonQuery(string sql)

object ExecuteScalar(string sql)

Вы решили перейти на современный ORM (Entity Framework Core), который работает с DbContext и LINQ-запросами.
Миграция всей кодовой базы займет много времени, но новые модули уже пишутся с использованием EF Core.
Старые модули продолжают использовать ILegacyDataAccess, и их нельзя менять.

Условия:
	1.Нужно создать адаптацию, которая позволит старым модулям работать через EF Core
	2.Нужно преобразовывать SQL-запросы в LINQ или использовать FromSqlRaw() там, где это возможно
	3.Нужно управлять транзакциями: старый код использует явные BeginTransaction() и Commit(), EF Core работает с SaveChanges()
	4.Нужно сохранить единый контекст базы данных на всю операцию (чтобы не было конфликтов)
	5.Старый код может выполнять несколько запросов в рамках одной транзакции — адаптер должен это поддерживать
========================================================================
