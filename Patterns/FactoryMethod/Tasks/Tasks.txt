================================Задача 1================================
Разрабатывается аналитическая система, которая должна экспортировать отчеты в разные форматы:
PDF, Excel, CSV, HTML. Каждый формат имеет свою логику генерации (PDF требует сложной верстки,
Excel — работы с ячейками и формулами, CSV — простого форматирования с разделителями, HTML — создания DOM-структуры).
В будущем планируется добавить поддержку JSON, XML и Word.

Условия:
	1.Клиентский код (модуль генерации отчетов) не должен знать о конкретных классах экспортеров
	2.Добавление нового формата не должно требовать изменений в существующем коде генерации
	3.Каждый экспортер может требовать свои специфические параметры (например, для PDF — ориентацию страницы, для Excel — нужно ли защищать лист)
	4.Процесс экспорта состоит из нескольких этапов: создание документа, наполнение данными, финализация, сохранение
========================================================================

================================Задача 2================================
Вы разрабатываете фреймворк для создания десктопных приложений,
которые должны работать на Windows, macOS и Linux с нативным внешним видом.
В зависимости от операционной системы, нужно создавать соответствующие компоненты:
кнопки, окна, чекбоксы, текстовые поля, списки.
Каждая платформа имеет свои классы реализаций, но клиентский код должен работать с единым интерфейсом.

Условия:
	1.Приложение не должно содержать условных операторов (if/switch), проверяющих текущую ОС
	2.В рантайме система должна автоматически определять платформу и создавать нужные компоненты
	3.Фреймворк должен позволять добавлять поддержку новых платформ (например, iOS, Android) без изменения существующего кода приложений
	4.Компоненты могут создаваться в разных контекстах: при инициализации окна, при динамическом добавлении элементов, при перестроении интерфейса
========================================================================

================================Задача 3================================
Интернет-магазин интегрируется с разными платежными шлюзами: PayPal, Stripe, ЮMoney, Qiwi, Apple Pay.
Каждый шлюз имеет свой API, свой формат запроса, свою логику авторизации, обработки ответов и верификации платежей.
При оформлении заказа система должна создать соответствующий процессор платежа в зависимости от выбранного пользователем способа оплаты.

Условия:
	1.Логика создания процессора зависит от нескольких факторов: способ оплаты, валюта, страна пользователя, сумма заказа, наличие промокода
	2.Каждый платежный процессор требует свои специфические данные (PayPal — email, Stripe — токен карты, ЮMoney — номер кошелька)
	3.Клиентский код оформления заказа не должен содержать логику выбора и инициализации конкретного процессора
	4.Платежные системы могут добавляться или удаляться в любой момент без рефакторинга основного кода магазина
========================================================================

================================Задача 4================================
Требуется написать инструмент для автоматической генерации тестовых данных в базу данных для нагрузочного тестирования.
Инструмент должен уметь генерировать разные типы сущностей: пользователи (имена, email, телефоны, адреса),
заказы (даты, суммы, статусы, товары в заказе), товары (названия, цены, категории, остатки),
отзывы (текст, рейтинг, дата). Каждый тип данных имеет свою логику генерации и свои правила валидности.

Условия:
	1.Генератор должен легко расширяться новыми типами сущностей
	2.Для каждого типа данных могут быть свои правила: для email — уникальность, для телефонов — формат, для сумм — диапазон значений
	3.Генерация может происходить в разных режимах: единичная запись, пакетная вставка, потоковая генерация
	4.Инструмент должен уметь генерировать связанные данные (например, заказы должны ссылаться на существующих пользователей)
========================================================================

================================Задача 5================================
Вы пишете инструмент для анализа лог-файлов, который должен поддерживать разные форматы логов:
Apache/Nginx access logs, системные логи (syslog), JSON-логи, пользовательские логи приложений с произвольным форматом.
Каждый тип лога требует своего парсера, своей логики извлечения полей (IP, timestamp, уровень важности, сообщение) и своей стратегии обработки ошибок.

Условия:
	1.Инструмент должен автоматически определять формат лога по расширению файла или первой строке
	2.Парсер для каждого формата может иметь свои настройки (разделители, паттерны регулярных выражений, правила пропуска строк)
	3.После парсинга данные могут быть экспортированы в разные целевые форматы (база данных, CSV, Elasticsearch)
	4.Добавление поддержки нового формата логов не должно затрагивать уже существующие парсеры и основной цикл анализа
========================================================================
