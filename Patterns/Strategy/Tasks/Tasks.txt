================================Задача 1================================
В приложении для работы с файлами нужно реализовать поддержку разных алгоритмов сжатия: ZIP, RAR, GZIP, 7z.
Пользователь может выбрать любой алгоритм в настройках.
Каждый алгоритм имеет свой формат вызова, свои параметры и свою степень сжатия. Алгоритмы могут добавляться со временем.

Условия:
	1.Базовый интерфейс с методом byte[] Compress(byte[] data) и byte[] Decompress(byte[] data)
	2.Есть класс FileManager, который использует алгоритм сжатия
	3.Пользователь может сменить алгоритм в любой момент
	4.Добавление нового алгоритма не должно менять код FileManager
========================================================================

================================Задача 2================================
Интернет-магазин работает в разных странах: США, Германия, Франция, Россия.
В каждой стране своя формула расчета налога: US — 10% от суммы, Germany — 19% + экологический сбор 5€,
France — 20% для товаров дороже 100€ и 10% для остальных, Russia — 20% НДС. Страна определяется по адресу доставки.

Условия:
	1.Интерфейс с методом decimal CalculateTax(Order order)
	2.Класс Order содержит сумму и страну доставки
	3.Налоговая ставка может зависеть от типа товаров или суммы заказа
	4.Нужно легко добавлять новые страны без изменения основного кода
========================================================================

================================Задача 3================================
В системе регистрации нужно проверять разные поля: email, телефон, пароль, возраст. Каждое поле имеет свои правила валидации:
Email: должен содержать @ и точку после @,
Телефон: 10-11 цифр, может начинаться с +,
Пароль: минимум 8 символов, цифра, заглавная буква,
Возраст: от 18 до 99 лет,
Правила могут меняться со временем. Нужно иметь возможность проверять любое поле любым способом.

Условия:
	1.Интерфейс IValidator с методом bool IsValid(string input)
	2.Класс ValidationService использует любой алгоритм для проверки
	3.Варианты проверки можно комбинировать (например, сначала проверить длину, потом формат)
	4.Новые типы валидации добавляются без изменения сервиса
========================================================================

================================Задача 4================================
Мобильное приложение-навигатор может строить маршруты разными способами: самый быстрый (учитывает пробки и лимиты скорости),
самый короткий (минимальное расстояние), самый экономичный (минимальный расход топлива),
экологичный (избегает загруженных районов). Пользователь переключает режим одним переключателем.

Условия:
	2.Класс Navigator использует выбранный механизм поведения
	3.Каждый механизм использует одни и те же данные карты, но по-разному
	4.Механизмы могут иметь свои внутренние параметры (например, вес пробок для быстрого маршрута)
========================================================================

================================Задача 5================================
В приложении нужно кэшировать результаты тяжелых вычислений.
Доступны разные методы вытеснения кэша: LRU (наименее давно использованный),
FIFO (первым пришел — первым ушел), LFU (наименее часто используемый),
TTL (удалять записи старше N секунд). Пользователь или администратор может выбрать метод в зависимости от нагрузки.

Условия:
	1.Интерфейс Вашеимя<TKey, TValue> с методами OnGet(TKey key), OnSet(TKey key, TValue value), GetEvictionKey()
	2.Класс Cache<TKey, TValue> использует выбранный метод для управления памятью
	3.Методы можно менять во время работы кэша
	4.При добавлении нового метода кэш не должен меняться
========================================================================
